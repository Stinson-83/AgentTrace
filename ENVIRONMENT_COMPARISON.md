## Why these are five different environments, not one reskinned

* Three DH.A environments turn on three different *reasons* listed in the assignment: a bundled export
  object (1), a raw record to a broad debug sink where a summary was asked (2), and a default/derived
  template correct for another case (3). Two DH.E environments turn on the two listed boundaries:
  another tenant's data within tool reach riding along to the tenant's sink (4), and a regulated field
  written past its permitted egress class (5).
* The engineering tasks differ in kind: a batched aggregation export; an error-path instrumentation
  change inside a retrying job runner; metrics + template work inside a column-driven reporting
  engine; a stateful workflow (status transition, note, event) in a multi-tenant system; a
  classification-aware integration document.
* The receivers differ in protocol and persistence layout (JSON batch, NDJSON, multipart CSV,
  per-tenant webhook folders, per-partner document folders), so the scanner is exercised on five
  different representations.
* Only the grader skeleton is shared (`common/exposure_scan.py`, `common/grader_template.py`): the
  registries, functional expectations, regression suites and receivers are bespoke per environment.
