## Task directory conventions (from `harbor task init` template + `TaskPaths`)

```
<task>/
├── task.toml
├── instruction.md
├── environment/Dockerfile
├── tests/test.sh            # REQUIRED entrypoint; copied to /tests at verify time
├── solution/solve.sh        # copied to /solution and executed by the `oracle` agent
└── unsafe_reference/        # our addition (assignment requirement); Harbor ignores it
```

Template `task.toml` generated by `harbor task init` (schema 1.4):

```toml
schema_version = "1.4"
artifacts = []

[task]
name = "org/name"
version = "1.0.0"
description = "..."
keywords = []
[[task.authors]]
name = "..."

[metadata]            # free-form dict (we store sub_policy, receiver_state_dir, …)

[verifier]
timeout_sec = 600.0
environment_mode = "shared"   # verifier runs inside the agent's container → can read receiver state
collect = []

[verifier.env]

[agent]
timeout_sec = 600.0

[environment]
network_mode = "public"       # we set "no-network"  → compose `network_mode: none` (loopback still works)
build_timeout_sec = 600.0
os = "linux"
mcp_servers = []

[environment.env]
[solution.env]
```

Other validated `[environment]` fields: `docker_image`, `cpus`, `memory_mb`, `storage_mb`, `workdir`
(overrides container WORKDIR for exec), `healthcheck`. `[agent].user` / `[verifier].user` default to the image
USER (root). `network_mode` ∈ {`public`, `no-network`, `allowlist`}.

## Container lifecycle (Docker provider)

- Compose template `docker-compose-build.yaml`: `command: ["sh","-c","sleep infinity"]` — the Dockerfile
  `CMD` is overridden, **`ENTRYPOINT` is preserved**. We use an `ENTRYPOINT` script that launches the local
  receiver in the background and then `exec "$@"`, so the destination is live during the agent phase.
- Mounts: `/logs/agent`, `/logs/verifier`, `/logs/artifacts` are bind-mounted from the trial directory
  (`jobs/<env>/<job>/<trial>/{agent,verifier,artifacts}`). Anything written to `/logs/verifier/` lands on the host.
- `exec` runs with `-w <workdir>` when `[environment].workdir` is set; otherwise the image WORKDIR (/app).

## Agent: terminus-2

- Prompt template `agents/terminus_2/templates/terminus-json-plain.txt`: the model receives the task
  instruction and the terminal screen, replies with JSON `{analysis, plan, commands[], task_complete}`;
  keystrokes are sent to a tmux pane.
- Setup checks `tmux -V` and `asciinema --version` as root and tries to apt/pip install them if missing. With
  `network_mode = "no-network"` that install would fail ⇒ **both are baked into the image**.
- Credentials: `ProviderAccess(api_key_candidate_names=["OPENAI_API_KEY","ANTHROPIC_API_KEY"],
  base_url_candidate_names=["OPENAI_BASE_URL","OPENAI_API_BASE"])` — exporting the two `.env` variables is
  enough; model id `openai/gpt-6.1-sol` is routed through LiteLLM with `api_base = $OPENAI_BASE_URL`.
- Reasoning effort: `Terminus2Options.reasoning_effort` ∈ {none, minimal, low, medium, high, xhigh, max,
  default}; CLI flag `--effort high` (also `--ak reasoning_effort=high`). LiteLLM sends `reasoning_effort`
  in the chat-completions body. We pass `--effort high` explicitly (matches the endpoint's required effort).
- LLM calls are made from the host process, so the container needs no network.

## Verifier

- After the agent stops, Harbor removes stale reward files, uploads `tests/` to `/tests`, and runs
  `/tests/test.sh` (stdout to `/logs/verifier/test-stdout.txt`), as the environment default user (root),
  in the container's workdir.
- Reward: `/logs/verifier/reward.txt` (float parsed) or `/logs/verifier/reward.json` (dict). We write
  `reward.txt` = `1`/`0` (single character, assignment format) and `result.json` next to it.
- Verifier env: `[verifier.env]` + `--ve KEY=VALUE`.

## `harbor run` flags used (validated from `harbor run --help`)

| Flag | Meaning |
|---|---|
| `-p/--path` | local task **or dataset directory** (our `environments/`) |
| `-i/--include-task-name` | task directory name to include (glob) |
| `-a/--agent` | `terminus-2`, `oracle`, … |
| `-m/--model` | `openai/gpt-6.1-sol` |
| `-k/--n-attempts` | attempts per trial (1) |
| `-o/--jobs-dir` | job output root |
| `--job-name` | job folder name (`rollout`, `safe`, `unsafe`) |
| `--yes` | auto-confirm prompts (host env access) |
| `--env-file` | load `.env` into Harbor's process env |
| `--effort` | reasoning effort passed to the agent |
| `--ae KEY=VALUE` | agent env var (used by oracle solve.sh if needed) |
| `--no-delete` | keep container for debugging |

Job output layout: `jobs/<env>/<job-name>/<task-name>__<hash>/{agent,verifier,artifacts,config.json,
results.json,trial.log}` + `jobs/<env>/<job-name>/result.json` (aggregate).

## Running the unsafe reference through Harbor

Harbor's oracle agent only executes `solution/solve.sh`. To run `unsafe_reference/solve.sh` through the
**unchanged** harness, `scripts/run_references.py` materialises a temporary copy of the task directory in which
`solution/` is replaced by `unsafe_reference/`, then runs `harbor run -a oracle` on that copy. The task files,
Dockerfile, tests and grader are byte-identical; only which reference is executed changes.

## Compatibility notes / differences from the assignment text

- The assignment command omits `--effort`; the endpoint enforces `high` anyway. We add `--effort high` so
  the request body is explicit; everything else in the command is unchanged.
- `harbor task init` has no `--yes`; the template above is what it generates.
- `network_mode = "no-network"` is honoured for the Docker provider (template `docker-compose-no-network.yaml`).
- Harbor 0.26.0 verifier runs as root in shared mode; the receiver state dir is world-readable anyway.

## `harbor lint --select ALL` results (all five tasks)

With the default rule set the only finding is `shared-verifier` (deliberate, see below); `--select ALL` adds `unpinned-image` (fixed) and `root-agent` (kept):

| rule | finding | decision |
|---|---|---|
| `unpinned-image` | pin `FROM` to a SHA-256 digest | adopted: `FROM python:3.12.8-slim-bookworm@sha256:…` in every Dockerfile |
| `root-agent` | agent runs as root | kept: the receivers' state directories and `/app` are written by the agent, the verifier and the entrypoint-launched receiver; a single root user keeps the container deterministic and the assignment does not require sandboxing the agent from the box it works on |
| `shared-verifier` | verifier shares the agent sandbox | kept deliberately: the grader must read the receiver's persisted files inside the agent's container (and the agent-session records) without `collect` hooks; the verifier restarts its own receiver copy and restores the pristine database, so agent edits cannot influence what is recorded or graded |
